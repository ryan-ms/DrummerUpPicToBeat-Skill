# 鼓譜 → DrummerUp .dmup

目標：產生一個 `.dmup` 檔，使用者在 DrummerUp 按「儲存 ▾ ▸ 匯入模組」就能直接開啟。

**DrummerUp 只收 `.dmup` 檔**（2026-10 起）：內容是 JSON，外面包一層 `{"format":"drummerup","version":1,"kind":…}` 標頭，
副檔名也一定要是 `.dmup`；以前的 `.json` 模組檔 App 已經不收。

**不要直接手寫 DrummerUp 的模組**：它要求每個樂器都有一條跟總格數一樣長的陣列，
手寫很容易數錯一格就整份錯位。一律先寫成「文字格線」（tab JSON），再用
`scripts/build_pattern.py` 轉檔——script 會檢查每小節格數，錯了會精確指出哪一行。

## 流程

0. **整理輸入（多張圖、截圖）。**
   - **順序**：多張圖依上傳順序當作演奏順序。圖上有頁碼、段落標記（A、B、Verse…）或明顯接續關係跟上傳順序不同時，
     以譜面為準，並在回覆說明最後用的順序。真的判斷不出來就先問。
   - **找出譜的位置**：截圖常夾著狀態列、留言、人物，譜只佔一部分。先跑
     ```bash
     python scripts/crop_sheet.py 圖1.png 圖2.jpg ... -o crops --rows --debug
     ```
     依參數順序輸出 `01-…-sheet.png`（整塊譜面，含上方標題、速度）、`01-…-row1.png`…（逐行放大）、
     `01-…-debug.png`（藍 = 偵測到的譜線，紅 = 裁切範圍）。**先看 debug 圖確認框對了**，再讀裁切後的圖。
   - script 印「找不到譜線」、debug 圖框錯，或環境沒有 Pillow／numpy（script 會說明）時，就自己看原圖判斷譜的範圍，
     用 Pillow 等工具裁切放大；連程式都不能跑就直接看原圖，但要聚焦在譜的區域。
     只有字母（例如 `K L R`）沒有譜線的圖，script 一定找不到，也照這個方式處理。
   - 如果圖裡根本沒有譜，就告訴使用者是哪幾張，不要硬讀。

0b. **影片（畫面上一段一段顯示譜）。** 教學影片常常每幾秒換一頁（例如 0–3 秒顯示第 1–4 小節、3–6 秒換成第 5–8 小節），
   或整排譜持續捲動。先跑
   ```bash
   python scripts/video_frames.py 影片.mp4 -o frames --rows --debug
   ```
   script 會找出每次換頁的時間，每頁存一張最清楚的畫面（`frames/frames/01_0m01.2s.png`…），
   再照 crop_sheet.py 的方式裁好（`frames/01_0m01.2s-sheet.png`、`-row1.png`、`-debug.png`），依時間排好就是演奏順序。
   游標、跟著演奏移動的高亮、淡入淡出的過場不會被當成換頁；只換其中一行也會抓到。
   - **先看 `frames/overview.png`**（所有頁的縮圖＋時間），確認沒有漏頁、沒有過場殘影；可疑的時間段再看那一頁的 debug 圖。
     換頁很快（一頁不到 1 秒）可以加 `--fps 8 --min-dur 0.4` 重跑；影片很長可以用 `--start 0:30 --end 2:10` 只跑有譜的那段。
   - 之後每一頁就當成一張截圖，照第 1、2 步讀譜、寫 tab JSON。每一頁的第一個小節照 script 印的寫
     `"source": "影片 0:03.2–0:06.0"`，build_pattern.py 才能檢查相鄰兩頁的交界。
   - **拼接（最重要）**：script 會比對相鄰兩頁的每一行，印出
     `第 1 行 = #03 第 1 行（跟上一張重複，拼接時只寫一次）`——常見於「只換下半頁」或往上捲動的影片，
     重複的行**只寫一次**；沒標的行就是新內容。`segments.json` 的 `same_rows` 是同樣的資訊。
   - `跟 #01 是同一頁`：影片後面又出現同一頁。看影片的性質判斷：跟著演奏的影片（譜面時間跟音樂同步）通常是反覆，照樣寫進去；
     最後回顧、片尾重播就不要重複。判斷不出來就照影片順序寫，並在回覆說明。
   - **捲動式的譜**（標「捲動」）：script 每捲過大約半個畫面存一張，相鄰兩張**一定有重疊**。
     以小節線、特徵明顯的小節對齊，從上一張最後讀到的小節之後接著寫，不要重複也不要跳過；
     對不上時看兩張之間的時間差、或請使用者確認。
   - **橫向捲動的譜（一整排譜往左捲，常見於 Facebook／IG 教學短片）**：`video_frames.py` 會把它當成「只有 1 頁」，
     或切成一連串「捲動」畫面但偵測到的譜面範圍不穩（很扁、只有幾 px 高、行數怪）。只要畫面上是一整排譜在影片裡往左移動，
     就改用：
     ```bash
     python scripts/scroll_stitch.py 影片.mp4 -o stitch
     ```
     它會每 0.1 秒取一格、算出每格往左捲了幾 px、遮掉固定不動的播放游標，拼成一條長譜：
     - 先看 `stitch/band.png`：紅框要剛好框住白底的譜（含手順字母），不能包到下面的影片畫面。框錯就看原畫面，
       用 `--band 上緣y:下緣y`（原始畫面像素）重跑。
     - 依序讀 `stitch/read_01.png`、`read_02.png`…：每張疊 4 段、每段跟下一段重疊約 60px，**重疊的音符只算一次**。
     - 拼接可能在開頭淡入或結尾停住時錯位：開頭和結尾的小節用 `video_frames.py` 存的單張畫面
       （或 `ffmpeg -ss 秒數 -i 影片 -frames:v 1 x.png` 截一張）再對一次。
     - 譜線很淡、只看得清一兩條時，用一段沒有音符的欄位量出五條線的 y 座標（看哪幾列偏暗）再判斷音高，不要用目測。
     - 開頭的預備休止小節、結尾的空小節不要寫進 tab JSON，交付時說明。
     - 譜上沒寫速度時，可以用「每小節捲過的 px ÷ 每秒捲動 px」估計影片的速度，跟預設 90 BPM 一起寫在回覆裡讓使用者參考，
       但 tab JSON 還是照規則不寫 `bpm`（除非使用者要求用估計值）。
   - 影片裡的譜太小、太糊（script 印「找不到譜線」、debug 圖框錯）時，請使用者換更高畫質的影片，
     或在每次換頁後各截一張圖改走截圖流程。
   - **環境讀不了影片**（script 印「這個環境沒有 ffmpeg…」）：先試 `pip install imageio-ffmpeg` 再跑一次；
     還是不行就告訴使用者兩個選擇，讓他挑：
     1. 改用電腦上的 **Claude Code** 處理影片：先裝 ffmpeg（Windows `winget install Gyan.FFmpeg`、macOS `brew install ffmpeg`，
        或 `pip install imageio-ffmpeg`）和 `pip install pillow numpy`，把這個 skill 資料夾放進 `~/.claude/skills/`，
        影片直接從硬碟讀、沒有上傳大小限制；
     2. 在影片每次換頁後各截一張圖上傳，改走截圖流程（任何環境都能用）。
     影片太大傳不上來時也是這兩個選擇。
   - 只看影片畫面上的譜，**不要從影片的聲音推測**沒寫在譜上的內容。

1. **讀譜。** 讀 [references/reading-drum-notation.md](references/reading-drum-notation.md)，
   照它把五線譜位置對應到樂器。PDF 先把每頁轉成圖片再看（例如 `pdftoppm -r 150 -png in.pdf page`），
   小節很密的譜就裁切放大逐行讀，不要一次看整頁就下結論。
   先抓出：標題、速度（♩=）、拍號、圖例、有沒有手順、反覆記號。
   **速度、拍號在譜上找不到、使用者也沒指定時，預設 4/4、90 BPM**（tab JSON 不寫 `bpm`／`time` 就是這個預設），
   不要自己從音樂風格猜。只有第一張圖會標速度和拍號是正常的，後面的圖沿用；後面的圖標了新的拍號或速度才改。

2. **寫 tab JSON。** 格式見 [references/tab-format.md](references/tab-format.md)，
   範例見 [examples/rock-beat.tab.json](examples/rock-beat.tab.json)。
   - 每小節選夠用的最小 grid（八分音符的律動用 2，有十六分才用 4）。
   - 用空白隔開每一拍，一拍一拍對著譜數。
   - 反覆記號預設展開成實際演奏順序（使用者另外要求才不展開）。
   - **多張圖（或影片的多頁）寫進同一個 tab JSON**，依順序接在 `bars` 裡，每張圖的第一個小節加 `"source": "圖 2"`
     （或檔名、影片時間），script 會在預覽標出每張圖從哪一小節開始，並檢查截圖重疊。
   - **截圖重疊**：連續截圖常常重複截到同一行。寫之前先比對前一張的最後一行和下一張的開頭，
     同一行只寫一次。

3. **轉檔。**
   ```bash
   python scripts/build_pattern.py song.tab.json -o 歌名.dmup
   ```
   有錯就照錯誤訊息修 tab 再跑，直到成功。
   - DrummerUp 一個模組最多 30 小節。超過時 script 會切成「歌名 (1/3)」「歌名 (2/3)」…幾個模組，
     **放進同一個群組檔**（`kind: "group"`，一樣是一個 `.dmup`），使用者匯入一次就會在模組庫多一個群組、全部模組都在裡面
     （小節編號接續全曲）。一個群組最多 20 個模組（600 小節），再長才會拆成 `歌名-1.dmup`、`歌名-2.dmup`。
   - 使用者想要分開的模組檔就加 `--separate`。
   - `⚠️ …完全一樣`：相鄰兩張圖的交界有一模一樣的小節。回頭看原圖：是截圖重疊就刪掉一份重跑；
     譜上本來就重複演奏就保留，並在回覆說明。
   - `ℹ️ 譜上沒寫，…用預設…`：有用到預設速度／拍號，交付時一定要寫出來。

4. **對照檢查。** script 會印出每小節的文字預覽，拿它**逐小節跟原譜比一次**
   （特別是小節數、每拍第一個音、重音位置、三連音）。發現錯就回第 2 步改。

5. **交付。** 把 `.dmup` 檔給使用者下載，並簡短說明：
   - 幾個小節、拍號、BPM。用了預設值要明講，例如「譜上沒標速度和拍號，先用預設 4/4、90 BPM，
     要改可以在 DrummerUp 裡調，或告訴我重新轉」。
   - 多張圖時：用了什麼順序、每張圖對應第幾到第幾小節、刪掉了哪些重疊的小節、哪些圖沒有譜。
   - 影片時：找到幾頁、每頁（影片幾秒到幾秒）對應第幾到第幾小節、哪些重複的行／頁刪掉或保留了。
   - 有哪些地方是猜的或換成近似樂器（例如第 4 顆 Tom 併入 Floor Tom、滾奏展開成十六分音符）。
   - 匯入方式：DrummerUp ▸ 儲存按鈕旁的 ▾ ▸「匯入模組」▸ 選這個檔案（群組檔也是同一個入口，或模組庫左側的「匯入群組」）。
     匯入前會先跳出預覽視窗，確認後才存進模組庫，不會蓋掉正在編輯的模組。
   - 只說「在 DrummerUp 匯入這個 .dmup 檔」就好，**不要提**副檔名可能被改成 `.json`、`.txt`、要改回 `.dmup` 之類的提醒。

## 沒辦法執行程式的環境

如果這個 AI chat 不能跑 Python，才直接寫最終的 .dmup 內容，規則見
[references/drummerup-json.md](references/drummerup-json.md)。寫完務必自己逐條核對長度公式，
並提醒使用者：存檔時副檔名要是 `.dmup`；匯入後如果小節內容錯位，就是某條陣列長度數錯了。

## 注意

- 用使用者的語言回覆（中文譜就用繁體中文）。
- 看不清楚、不確定的地方要明講，不要默默猜；整頁都看不清楚就請使用者給更清楚的圖。
- DrummerUp 只有 9 個樂器軌道（crash, ride, hihat, tom1, tom2, tom3, snare, kick, hihatFoot），
  沒有滾奏、力度漸強、音長，這些都要在回覆中說明怎麼近似處理的。
